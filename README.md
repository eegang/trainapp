# trainapp — личный Telegram-бот: вес, еда, тренировки, сон, работа, заработок

Бот отвечает только владельцу (`ALLOWED_USER_IDS`), остальным не отвечает вовсе.

## Меню

Главное меню — два раздела:

```
📝 Записать        👀 Смотреть
```

**📝 Записать** — то, что вводишь руками:

```
📈 Вес        🍎 Еда
💪 Тренировка 😴 Сон
🕒 Работа
🔙 Назад
```

**👀 Смотреть** — сводки и выгрузки:

```
📊 Сегодня    💰 Заработок
📤 Отчёт за 30 дней
🔙 Назад
```

| Кнопка | Что делает |
|---|---|
| 📈 Вес | Текущий вес и запись в историю |
| 🍎 Еда | Калории за **сегодня** или **вчера** (несколько записей суммируются) |
| 💪 Тренировка | Описание тренировки одним сообщением |
| 😴 Сон | Одна кнопка-переключатель: первое нажатие — заснул, второе — проснулся |
| 🕒 Работа | Часы за день: сегодня, вчера или любая дата |
| 📊 Сегодня | Сводка: вес, калории, тренировки, работа, сон |
| 💰 Заработок | Ставка один раз → расчёт за текущий и все прошлые месяцы |
| 📤 Отчёт за 30 дней | `.txt`-файл для анализа в GPT |

Команды: `/start` — меню, `/cancel` — отменить текущий ввод.

Пока бот ждёт число (вес, калории, часы, ставку), **любая кнопка меню всё равно
работает** — ввод сбрасывается и открывается нужный раздел.

## Рабочее время и заработок

**🕒 Работа** — внести часы за день:

1. День: «Сегодня», «Вчера» или дата текстом (`20.10`, `20.10.2026`).
2. Часы: `8`, `8,5`, `8:30`, `8ч30`, `8 часов 30 минут`, `480мин`.
3. Заметка в той же строке: `8:30 закрывал год`.

Повторный ввод за тот же день **заменяет** значение (бот покажет «было …»),
это способ исправить опечатку. `0` убирает день из учёта.

**💰 Заработок** — ставка задаётся один раз и хранится в `settings`:

```
💰 Заработок
Ставка: 850 за час

Октябрь 2026 · сейчас · 8 ч 30 мин за 1 дн. = 7 225

Предыдущие месяцы:
  Сентябрь 2026 · 12 ч за 2 дн. = 10 200

Итого: 20 ч 30 мин · 3 дн. = 17 425
```

Ставка меняется кнопкой под расчётом. Сумма = часы × ставка.

## Установка

```bash
pip install -r requirements.txt
copy .env.example .env        # Windows; на Linux/macOS: cp
```

В `.env` обязательно:

```
BOT_TOKEN=...               # от @BotFather
ALLOWED_USER_IDS=123456789  # твой Telegram user_id, несколько — через запятую
```

Без `ALLOWED_USER_IDS` бот не запустится: закрытие от посторонних — не опция.

```bash
python main.py              # запуск
python tests/smoke.py       # прогон сценариев после любых правок
```

## Структура проекта

```
main.py                  точка входа
config.py                настройки из .env (токен, владельцы, путь к базе)
app/
  menu.py                ЕДИНСТВЕННОЕ место с подписями, раскладкой и обработчиками кнопок
  bot.py                 Bot, Dispatcher, подключение защиты владельца
  access.py              middleware: отвечаем только ALLOWED_USER_IDS
  navigation.py          переход в раздел из середины ввода (берёт всё из menu.py)
  states.py              FSM-состояния диалогов
  dates.py               даты, диапазоны, разбор «20.10», «вчера»
  duration.py            разбор и форматирование часов и минут
  money.py               ставка, суммы, форматирование денег
  prefs.py               настройки пользователя (ставка)
  report.py              текст отчёта и сводки за сегодня
  handlers/              по модулю на раздел: common, weight, meals, exercises,
                         sleep, work, payout, export, fallback
db/
  schema.py              таблицы, миграции, сверка схемы при старте
  repository.py          все запросы к базе (aiosqlite)
tests/smoke.py           сценарии через настоящий Dispatcher, без сети
```

### Как добавить раздел

1. В `app/menu.py`: подпись-константа, строка в `LAYOUT`, запись в `HANDLERS`.
2. Обработчик в `app/handlers/<раздел>.py` с фильтром `F.text == <подпись>`,
   модуль добавить в `app/handlers/__init__.py`.
3. Если раздел ждёт ввод — начинать ввод с `forward_to_menu`, иначе кнопки
   меню в этом состоянии не сработают.
4. Новые таблицы и колонки — в `db/schema.py`: `CREATE_TABLES` **и**
   `EXPECTED_COLUMNS`. `CREATE TABLE IF NOT EXISTS` не дополняет существующие
   таблицы, поэтому без `EXPECTED_COLUMNS` колонка на старой базе не появится.
5. Тест в `tests/smoke.py`.

## База данных

SQLite: `users`, `weight_entries`, `meals`, `exercises`, `sleep`, `work_days`,
`settings`. Рабочие часы — одна строка на день (`UNIQUE(user_id, date)`).
Ставка и прочие настройки — пары ключ-значение в `settings`.

При каждом старте `init_db()`:

1. создаёт недостающие таблицы;
2. переименовывает исторические колонки (`users.current_weight` → `weight`);
3. переносит старую `work_sessions` в `work_days`, суммируя записи одного дня;
4. дописывает недостающие колонки из `EXPECTED_COLUMNS`;
5. сверяет схему и пишет в лог, если что-то не сходится.

Все шаги неразрушающие. Резервная копия перед крупными изменениями:

```bash
copy training_bot.db training_bot.db.bak
```

`*.db` и `*.bak` не попадают в git.
