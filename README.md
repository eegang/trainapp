# trainapp — Telegram-бот для учёта тренировок, питания и рабочего времени

Личный бот: вес, калории, тренировки, сон и учёт рабочих часов. Умеет
выгружать отчёт за 30 дней текстом — его можно скормить GPT для анализа.

## Возможности

| Кнопка | Что делает |
|---|---|
| Вес на сегодня | Сохраняет текущий вес, ведёт историю |
| Приемы пищи | Суммирует калории за **сегодня** или **вчера** |
| Показатели упражнений | Сохраняет описание тренировки |
| **Рабочее время** | Запись отработанных часов за день (сегодня/вчера/любая дата) |
| **Заработок** | Ставка задаётся один раз → расчёт за текущий и все прошлые месяцы |
| Данные за сегодня | Сводка: вес, калории, упражнения, работа, сон |
| Выгрузить данные за 30 дней | Отправляет .txt-отчёт для анализа в GPT |
| Я сплю / Я проснулся | Таймер сна с подсчётом длительности |

Команды: `/start` — главное меню, `/cancel` — прервать текущее действие.

## Рабочее время и заработок

**Рабочее время** — одна функция: внести часы за день.

1. Нажимаешь кнопку и выбираешь день: «Сегодня», «Вчера» или дата с
   клавиатуры (`20.10`, `20.10.2026`, `2026-10-20`).
2. Пишешь количество часов. Понимается `8`, `8,5`, `8.75`, `8:30`, `8ч30`,
   `8 часов 30 минут`, `480мин`.
3. Заметка — в той же строке: `8:30 закрывал год`.

Значение привязано к дате: **повторный ввод за тот же день заменяет его**, а
не добавляет вторую строку. Это и есть способ исправить опечатку — бот
покажет «было 8 ч 30 мин» → «9 ч». Ввод `0` убирает день из учёта. Ответ
сразу показывает итог месяца, а при заданной ставке — деньги.

**Заработок** — ставка задаётся один раз (лежит в `settings`), дальше кнопка
показывает расчёт:

```
💰 Заработок
Ставка: 850 за час

Октябрь 2026 · сейчас · 8 ч 30 мин за 1 дн. = 7 225

Предыдущие месяцы:
  Сентябрь 2026 · 12 ч за 2 дн. = 10 200

Итого: 20 ч 30 мин · 3 дн. = 17 425
Средний день: 6 ч 50 мин · 5 808,33
```

Ставка меняется кнопкой под сообщением, границы 0,01–10 000 000. Сумма =
`часы × ставка`; без ставки показываю только часы.

Защита от ошибочного ввода: больше 24 часов за день не принимается, дата и
ставка проверяются, непонятный текст — переспрос, а не тихий отказ.

## Установка

```bash
# 1. Зависимости
pip install -r requirements.txt

# 2. Файл с токеном
copy .env.example .env        # Windows
# cp .env.example .env        # Linux / macOS

# 3. Впишите в .env токен от @BotFather
#    BOT_TOKEN=123456789:AA...

# 4. Запуск
python main.py

# 5. Проверка после любых правок
python tests/smoke.py
```

## Безопасность токена

Токен **не должен** лежать в коде или попадать в git.

1. Откройте @BotFather → `/mybots` → выберите бота → **API Token** →
   **Revoke current token**.
2. Сгенерируйте новый токен и впишите его в `.env`.
3. `.env` уже в `.gitignore`.

Если токен когда-либо публиковался, его нужно перевыпустить: Telegram не
скрывает токены от ботов, которые их увидят.

### Как добавить новый раздел

1. Текст кнопки — константой в `app/keyboards.py` и в `main_keyboard()`.
2. Состояния — в `app/states.py`, хендлеры — новым модулем в `app/handlers/`.
3. Хендлер нового раздела — в таблицу `_menu()` в `app/navigation.py`,
   чтобы кнопка работала из чужого ввода.
4. Роутер — в `app/handlers/__init__.py`: навигация и кнопки до хендлеров
   состояний, `fallback` последним.
5. Запросы — в `db/repository.py`. Таблицу — в `db/schema.py`: `CREATE_TABLES`
   **и** `EXPECTED_COLUMNS` (или колонка не появится на уже существующей
   базе — см. «Схема и миграции»).
6. Сценарий — в `tests/smoke.py`.

## База данных

SQLite, таблицы: `users`, `weight_entries`, `meals`, `exercises`, `sleep`,
`work_days`, `settings`. Файл базы создавать вручную не нужно — он поднимется
при первом запуске.

Рабочие часы хранятся по одному ряду на день (`work_days`): `date` +
`duration_min` + необязательная `note`, с `UNIQUE(user_id, date)`. Ставка и
другие настройки лежат в `settings` парой ключ-значение, поэтому новая
настройка не требует изменения схемы.

### Схема и миграции

`CREATE TABLE IF NOT EXISTS` **не дополняет** уже существующую таблицу. Из-за
этого база, созданная старой версией кода, тихо роняет запросы с
`no such column`. Чтобы этого не случалось, `init_db()` при каждом старте:

1. создаёт недостающие таблицы;
2. переименовывает исторические колонки (`users.current_weight` → `weight`);
3. переносит устаревшую таблицу `work_sessions` (таймер + ручные записи) в
   `work_days`, суммируя несколько записей одного дня;
4. дописывает отсутствующие колонки из `EXPECTED_COLUMNS`;
5. сверяет схему и **внятно пишет в лог**, если чего-то не хватает.

Все шаги неразрушающие: данные строк не удаляются и не меняются.

Резервная копия:

```bash
copy training_bot.db training_bot.db.bak
```
