# trainapp — Telegram-бот для учёта тренировок, питания и рабочего времени

Личный бот: вес, калории, тренировки, сон и учёт рабочих часов. Умеет
выгружать отчёт за 30 дней текстом — его можно скормить GPT для анализа.

## Возможности

| Кнопка | Что делает |
|---|---|
| Вес на сегодня | Сохраняет текущий вес, ведёт историю |
| Приемы пищи | Суммирует калории за **сегодня** или **вчера** |
| Показатели упражнений | Сохраняет описание тренировки |
| **Рабочее время** | Отдельный блок: таймер смены, ручные записи, статистика против нормы |
| Данные за сегодня | Сводка: вес, калории, упражнения, работа, сон |
| Выгрузить данные за 30 дней | Отправляет .txt-отчёт для анализа в GPT |
| Я сплю / Я проснулся | Таймер сна с подсчётом длительности |

Команды: `/start` — главное меню, `/cancel` — прервать текущее действие.

## Блок «Рабочее время»

Внутри — своё меню (`Рабочее время` → кнопки):

- **▶ Начать работу / ■ Завершить работу** — таймер смены. Повторный старт
  не создаёт вторую сессию.
- **Записать вручную** — день (кнопка «Сегодня»/«Вчера» или дата `20.10`) и
  длительность. Понимает `8`, `8,5`, `8.75`, `8:30`, `8ч30`, `480мин`,
  `8 часов 30 минут`. Заметка дописывается в ту же строку:
  `8:30 закрывал год`.
- **Статистика** — переключение день / неделя / месяц инлайн-кнопками,
  прогресс-бар, сравнение с нормой, разбивка по дням и среднее.
- **Удалить запись** — список последних записей кнопками, удаление только
  после подтверждения; чужие записи не удаляются (фильтр по `user_id`).
- **Норма часов** — своя норма в день и в неделю (по умолчанию 8 и 40).
  Валидация диапазона: 0,5–24 ч в день, 1–168 ч в неделю.

Две защиты от типичных ошибок учёта:

1. **Забытая сессия.** Если таймер висит больше суток, бот не пишет 30 часов
   молча — спрашивает «Сохранить как есть или удалить?».
2. **Границы значений.** Вес вне 1–500, калории ≤ 0, длительность > 24 ч и
   норма вне диапазона отклоняются с внятными подсказками.

Неделя начинается с понедельника. Месячная норма считается по рабочим дням
(пн–пт) внутри периода. Смена через полночь относится к дате начала.

## Установка

```bash
# 1. Зависимости
pip install -r requirements.txt

# 2. Файл с токеном
copy .env.example .env        # Windows
# cp .env.example .env        # Linux / macOS

# 3. Впишите в .env токен от @BotFather
#    BOT_TOKEN=123456789:AA...

# 4. Запуск
python main.py

# 5. Проверка после любых правок
python tests/smoke.py
```

## Безопасность токена

Токен **не должен** лежать в коде или попадать в git.

1. Откройте @BotFather → `/mybots` → выберите бота → **API Token** →
   **Revoke current token**.
2. Сгенерируйте новый токен и впишите его в `.env`.
3. `.env` уже в `.gitignore`.

Если токен когда-либо публиковался, его нужно перевыпустить: Telegram не
скрывает токены от ботов, которые их увидят.

## Структура проекта

```
trainapp/
├── main.py              точка входа
├── config.py            настройки из .env
├── app/
│   ├── bot.py           Bot и Dispatcher
│   ├── keyboards.py     тексты кнопок (константы) и клавиатуры
│   ├── states.py        FSM-состояния
│   ├── dates.py         даты и диапазоны (неделя с пн)
│   ├── duration.py      разбор «8:30», форматирование, прогресс-бары
│   ├── prefs.py         настройки пользователя и значения по умолчанию
│   ├── navigation.py    кнопки разделов работают прямо во время ввода
│   ├── report.py        сборка отчётов и сводок
│   └── handlers/        по одному модулю на раздел
├── db/
│   ├── schema.py        создание таблиц
│   └── repository.py    запросы к БД (aiosqlite)
├── tests/smoke.py       сценарии через настоящий Dispatcher
└── training_bot.db      база данных (в git не попадает)
```

### Как добавить новый раздел

1. Текст кнопки — константой в `app/keyboards.py` и в `main_keyboard()`.
2. Состояния — в `app/states.py`, хендлеры — новым модулем в `app/handlers/`.
3. Хендлер нового раздела — в таблицу `_menu()` в `app/navigation.py`,
   чтобы кнопка работала из чужого ввода.
4. Роутер — в `app/handlers/__init__.py`: навигация и кнопки до хендлеров
   состояний, `fallback` последним.
5. Запросы — в `db/repository.py`, таблицу — в `db/schema.py`
   (`CREATE TABLE IF NOT EXISTS` применится к существующей базе сам).
6. Сценарий — в `tests/smoke.py`.

## База данных

SQLite, таблицы: `users`, `weight_entries`, `meals`, `exercises`, `sleep`,
`work_sessions`, `settings`. Схема создаётся автоматически при старте —
файл базы создавать вручную не нужно, новые таблицы добавляются к
существующим без потери данных.

Рабочие сессии хранятся одной таблицей для таймера и ручного ввода:
активная сессия — `start_time` без `end_time`, готовая запись — любой ряд с
`duration_min`. Настройки (`work_hours_per_day`, `work_hours_per_week`)
лежат в `settings` как ключ-значение, поэтому новые настройки не требуют
миграции схемы.

Резервная копия:

```bash
copy training_bot.db training_bot.db.bak
```
